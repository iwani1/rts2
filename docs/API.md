# API inventory — Phase 1A

All company-scoped routes require an authenticated session and re-check authorization in the service layer. The `{companyId}` in the URL is not trusted as proof of access; service queries filter by tenant. Mutations are audited. Imports use fixed templates, require an explicit reason at commit, and follow D-024 all-or-nothing behavior. Endpoint implementation does not imply acceptance: PostgreSQL integration and browser verification remain outstanding for several slices; see `docs/PROGRESS.md`.

| Method | Path | Status | Behavior |
|---|---|---|---|
| GET | `/api/health` | Implemented | Minimal uncached liveness response; does not probe dependencies. |
| GET | `/api/health/ready` | Implemented | Performs a PostgreSQL `SELECT 1`; returns 200 when ready or a generic, uncached 503 when unavailable. |
| GET/POST | `/api/auth/[...all]` | Implemented | Better Auth email/password sign-in, session query/revocation, password change and rate limits. Public sign-up is disabled. Requires generated Prisma Client, applied migrations, PostgreSQL, `AUTH_SECRET` and `APP_URL`. |
| GET/POST | `/api/admin/users/{userId}/roles` | Implemented, Super Administrator only | Lists role history/catalogue or assigns a role with company scope and required reason. Actor identity is derived from the session. |
| DELETE | `/api/admin/role-assignments/{assignmentId}` | Implemented, Super Administrator only | Revokes an assignment with required reason; prevents self-escalation and audits transactionally. |
| GET | `/api/admin/audit-events` | Implemented, Super Administrator only | Returns a private, cursor-paginated audit page; excludes IP addresses and disables caching. |
| GET/PUT | `/api/admin/companies/{companyId}/settings` | Implemented, Super Administrator only | Returns registered setting status without values, or writes an explicitly supplied JSON value with a reason and audit event. No defaults are exposed. |
| GET | `/api/admin/companies/{companyId}/resource-buffers` | Implemented, Super Administrator | Reads only the two typed RNT-03 buffer values for the dedicated settings form; unset values are returned as `null`. No default is created. |
| GET | `/api/admin/companies/{companyId}/quote-validity` | Implemented, Super Administrator | Reads only the typed quotation-validity duration in whole days; unset value is `null`, with no default. |
| GET | `/api/admin/companies/{companyId}/pricing-models` | Implemented, Super Administrator | Reads only operator-entered typed rental pricing lines; unset is `null`. Rates are expressed as integer GHS pesewas. No pricing or quotation calculation is performed. |
| GET | `/api/admin/companies/{companyId}/tax-lines` | Implemented, Super Administrator | Reads only operator-entered tax/levy labels and rates in integer basis points; unset or cleared configuration is `null`. No tax arithmetic or compounding behavior is implemented. |
| GET | `/api/admin/companies/{companyId}/deposit-policy` | Implemented, Super Administrator | Reads only the explicitly configured fixed amount, percentage, or no-deposit policy and due stage; unset is `null`. No payment collection or verification is implied. |
| GET/POST | `/api/companies/{companyId}/rental-requests/{requestId}/pricing-preview` | Implemented, `rental:manage`, Under Review only | Lists configured pricing models and returns a temporary internal pre-tax preview from selected models and supplied distance/request duration. No quote is saved or issued; taxes, discounts and deposits are excluded. |
| GET | `/api/companies/{companyId}/rental-requests/{requestId}/pricing-worksheets` | Implemented, `rental:manage`, Under Review only | Returns up to 20 newest immutable internal worksheet versions, uncached. |
| POST | `/api/companies/{companyId}/rental-requests/{requestId}/pricing-worksheets` | Implemented, `rental:manage`, Under Review only | Saves an immutable, reason-audited internal pricing worksheet version. It does not create or issue a quotation or change rental-request status. |
| GET/POST | `/api/companies/{companyId}/customers` | Implemented, authorized company scope | Search/paginate active customers or create one. Display name is required; optional fields remain unset unless supplied. |
| GET/PUT/DELETE | `/api/companies/{companyId}/customers/{customerId}` | Implemented, authorized company scope | Fetch customer and audit history, update with reason, or archive with reason. DELETE is soft archive, not physical deletion. |
| POST | `/api/companies/{companyId}/customers/import/preview` | Implemented, customer manager | Validates the fixed CSV template and returns row/file errors; duplicate supplied references are errors, while names are not treated as unique identifiers. No writes occur. |
| POST | `/api/companies/{companyId}/customers/import` | Implemented, customer manager | Creates and audits the entire valid batch atomically. Any invalid row rejects the batch; no silent skips or automatic updates/merges. |
| GET/POST | `/api/companies/{companyId}/drivers` | Implemented, full manager scope | Search/paginate active driver records or create a driver. Dispatcher and driver-own-profile projections remain fail-closed. |
| GET/PUT/DELETE | `/api/companies/{companyId}/drivers/{driverId}` | Implemented, full manager scope | Fetch, update with reason, or archive with reason. DELETE retains the archived record. |
| POST | `/api/companies/{companyId}/drivers/import/preview` | Implemented, driver manager | Validates the fixed CSV template. Possible same-name matches in the CSV or existing company records are advisory warnings only; they do not change `canImport`. |
| POST | `/api/companies/{companyId}/drivers/import` | Implemented, driver manager | Creates and audits each valid row as a new record in one transaction. A name match never skips, merges, updates, blocks or deduplicates a row; actual validation errors still reject the whole batch. |
| GET/POST | `/api/companies/{companyId}/vehicles` | Implemented, full manager scope for writes | Search/paginate active vehicles or create one. Fleet projections expose active block status/time; full managers also see the reason, while limited fleet projections do not. |
| POST | `/api/companies/{companyId}/vehicles/{vehicleId}/safety-blocks` | Implemented, Ops/Fleet Manager or Super Administrator | Immediately applies Under Maintenance, Out of Service or Pending Inspection with a required reason; active blocks cannot be replaced. |
| PUT | `/api/companies/{companyId}/vehicles/{vehicleId}/safety-blocks/{blockId}` | Implemented, authorized maintenance releaser | One-time release requires recorded work completion, passed inspection results, and reason; updates are transactionally audited and append-only apart from this release.
| GET/POST | `/api/companies/{companyId}/maintenance/work-orders` | Implemented, maintenance managers (company/global or Fleet Manager `APPROVE_RELEASE` scope) | Lists the latest 100 work orders with up to 50 newest reason-audited status-history events per record, or records an explicitly non-safety fault as `Reported`; responses are private/no-store. | PATCH | `/api/companies/{companyId}/maintenance/work-orders/{workOrderId}` | Implemented, maintenance managers | Executes only D-046 transitions; every change requires a reason, updates immutable sequenced status history, and writes audit atomically. Approval requires a different manager than the reporter; completion requires date and inspection results. |
| GET/PUT/DELETE | `/api/companies/{companyId}/vehicles/{vehicleId}` | Implemented, company-scoped | Fetch or update a vehicle, including a manager-authorized usual-driver link to an active same-company driver; DELETE archives. Mutations require a reason and are audited. File uploads are deferred pending production storage selection. |
| POST | `/api/companies/{companyId}/vehicles/import/preview` | Implemented, fleet manager | Validates the fixed CSV template; duplicate company registration numbers are row errors. No writes occur. |
| POST | `/api/companies/{companyId}/vehicles/import` | Implemented, fleet manager | Creates and audits the entire valid batch atomically. Invalid rows reject the batch; no silent skips or automatic updates/merges. |
| GET/POST | `/api/companies/{companyId}/rental-requests` | Implemented, Ops Manager/Super Administrator | Lists requests or creates a staff-entered Draft linked to an existing customer; Draft data may include an explicit return date. |
| GET/PUT | `/api/companies/{companyId}/rental-requests/{requestId}` | Implemented, authorized rental-request scope | Fetches a request or updates an existing Draft, including the explicit return date. Status transitions use the dedicated D-032 endpoint. |
| POST | `/api/companies/{companyId}/rental-requests/{requestId}/submit` | Implemented, Ops Manager/Super Administrator | Performs Draft → Submitted using D-023/D-030 validation; overnight return times require an explicit later return date. No quotation, availability, reservation, confirmation, dispatch or cancellation behavior is included. |
| POST | `/api/companies/{companyId}/rental-requests/{requestId}/transition` | Implemented, Ops Manager/Super Administrator | D-032 allows only Submitted → Under Review or Under Review → Declined. Requires an audited reason; no notification, quotation or resource operation is performed. |

The server-rendered `/rentals/reports` page is available to company/global `rental:manage` users as a tenant-scoped all-time aggregate of request statuses and sources plus an all-time count of audited `Draft → Submitted` events. It explicitly labels quotations/acceptance, confirmation/completion, financial values, utilization, and cancellation reasons as unavailable until their underlying workflows exist; it is not an API export or financial report.

The API inventory does not imply that remaining Phase 1A features are complete. Rental availability/conflict enforcement remains deferred under D-026–D-031 until the approved reservation effects are implemented with authorized booking transitions and an atomic resource ledger. Quotations, invoices, payments, safety work-order linkage, reservation-derived vehicle statuses, assignment prevention and public enquiries remain unimplemented or gated by owner decisions. D-044 provides non-safety work-order intake; D-045 adds separate auditable safety-block apply/release controls; D-046 adds a bounded, reason-audited work-order lifecycle with completion evidence. See `docs/PROGRESS.md`, `docs/DECISIONS.md` and `docs/OPEN_QUESTIONS.md` for status and boundaries.
